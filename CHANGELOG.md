## [Non publié] — Avril 2026 — Refonte du dialogue de persistance / convertisseur de fichiers

### Ajouts
- **Auto-correction des incohérences Sankey à la réconciliation / conversion** ([issue #134](https://gitlab.com/su-model/sankeyapplication/-/issues/134)). Nouvelle case **« Auto-correction »** dans le dialogue de réconciliation et du convertisseur (onglet *Options d'entrée*, groupe *Validation*, visible quand le format d'entrée est Excel). Quand elle est cochée, le serveur Flask `/optimize/launch_optim` court-circuite la réconciliation MFA et renvoie un fichier `<input>_corrected.xlsx` à la place du résultat habituel `<input>reconciled.xlsx`. Le fichier corrigé contient les éléments ajoutés (flux manquants dans IO/TER, flux référencés depuis les onglets secondaires sans correspondance dans la base, propagation parent → enfants) **plus les triggers** (lignes / cellules qui ont déclenché chaque correction) tous surlignés en rouge sur les onglets `IO` / `TER` / `IO_DATA` / `Noeuds` / `flux` / `data` / `min_max` / `constraints`. L'utilisateur revoit le fichier, ajuste si nécessaire, puis relance la réconciliation sur le fichier corrigé. La logique métier vit dans la fonction commune `SankeyExcelParser.io_base.run_autocorrect_pass`, partagée entre le CLI MFAProblem (`bin/run_reconciliation.py --autocorrect`) et le serveur Flask. Voir [OpenSankey CHANGELOG](submodules/OpenSankey+/submodules/OpenSankey/CHANGELOG.md), [SankeyExcelParser CHANGELOG](submodules/OpenSankey+/submodules/OpenSankey/submodules/SankeyExcelParser/CHANGELOG.md) et [MFAProblem CHANGELOG](submodules/MFAProblem/CHANGELOG.md).
- **Onglet *Récap licences* dans la modale d'accueil** : nouvel onglet (entre *Interactions souris...* et *Nouveautés*) qui affiche un tableau récapitulatif des fonctionnalités débloquées par chacune des trois licences applicatives — OpenSankey+, SankeySuite (AFM) et accès développeur. La matrice (13 fonctionnalités, 3 colonnes) est alimentée par une liste hardcodée dans `client/src/components/FeaturesMatrixSA.tsx`, dérivée d'un balayage des gates `has_sankey_plus` / `has_sankey_afm` / `has_sankey_dev` dans les 3 couches OS / OSP / SA. Traduit dans les 5 langues. Documenté dans [doc/sources/fr/user/features/recap_licences.rst](doc/sources/fr/user/features/recap_licences.rst).
- **Export animé des vues — GIF / WebM / séquence PNG** (sankeyanimation #76, OpenSankey+) : nouvelle entrée *Animation...* dans le menu **Exporter → Toutes les vues**. Modale draggable qui permet de sélectionner les vues à inclure et leur ordre, la durée par vue (défaut 1500 ms), le DPI (150 ou 300) et le mode de boucle (une fois / infinie / aller-retour). Trois formats : GIF animé (compatibilité universelle, 256 couleurs), WebM (vidéo, meilleure qualité), Séquence PNG zippée (frames numérotées). Le master n'est jamais inclus dans l'animation (canevas d'édition, pas une vue narrative). Le pipeline réutilise le point de service Flask `/opensankey/save/png` pour capturer chaque vue (même fidélité que l'export PNG simple), puis encode côté navigateur via `gifenc` ou `MediaRecorder`. Voir [doc/sources/fr/user/features/export_animation.rst](doc/sources/fr/user/features/export_animation.rst), le [changelog OpenSankey+](submodules/OpenSankey+/CHANGELOG.md) et le [changelog OpenSankey](submodules/OpenSankey+/submodules/OpenSankey/CHANGELOG.md). Nouvelle dépendance frontend : `gifenc 1.0.3`.
- **Sous-menu groupé *Toutes les vues* + tooltips de licence sur les items grisés** : les exports multi-vues (PNG zip, PDF fusionné, Animation) sont désormais regroupés sous une section titrée dans le menu Exporter, séparés des exports vue courante (PNG, PDF, SVG). Quand la licence OpenSankey+ n'est pas active, les items du sous-menu sont grisés avec un tooltip *« Cette fonctionnalité nécessite OpenSankey+ »* (au lieu d'un simple disabled muet). Les exports PNG / PDF simples restent libres avec ajout d'un watermark *« réalisé avec OpenSankey.fr »* en l'absence de licence.
- **Édition inline des labels** (#688) : trois nouvelles façons d'éditer le nom d'un nœud, la valeur d'un flux ou le label d'une zone de texte sans passer par le panneau de configuration : (1) double-click sur le texte, (2) entrée « Éditer le nom » dans le clic droit (sur les nœuds et les zones de texte), (3) taper une touche quand un seul élément est sélectionné ouvre l'éditeur pré-rempli avec ce caractère. Documenté dans la modale d'accueil (tableau des raccourcis, 5 langues). Voir [changelog OpenSankey](submodules/OpenSankey+/submodules/OpenSankey/CHANGELOG.md) et [changelog OpenSankey+](submodules/OpenSankey+/CHANGELOG.md).
- **Option « Générer les tags de niveau automatiques »** (#95) : nouvelle case à cocher dans *Options d'entrée* (base, groupe *Complétion*), **défaut décochée**. Quand elle est décochée (nouveau défaut), l'ouverture d'un fichier Excel ne génère plus de groupes `Dimension 1`, `Dimension 2`, ... à partir de la hiérarchie des nœuds. Règle additionnelle côté parser : même si l'option est cochée, une dimension auto seule (cas fréquent d'une hiérarchie à une seule branche) n'est jamais matérialisée en levelTag — elle induit en erreur en suggérant une antagonie qui n'existe pas. La hiérarchie parent-enfant reste inchangée, donc l'agrégation/désagrégation locale continue de fonctionner. Voir [changelog SankeyExcelParser](submodules/OpenSankey+/submodules/OpenSankey/submodules/SankeyExcelParser/CHANGELOG.md) et [changelog OpenSankey](submodules/OpenSankey+/submodules/OpenSankey/CHANGELOG.md).
- **Refonte UI du dialogue Ouvrir/Enregistrer/Convertisseur de fichiers** : sélecteurs Entrée/Sortie côte-à-côte en haut, bloc collapsible « Options » (fermé par défaut) contenant 3 onglets — *Options d'entrée*, *Options d'enregistrement*, *Mise en page*. L'onglet « Mise en page » est masqué dans le mode Convertisseur de fichiers (où il n'a pas de sens).
- **Options de lecture Excel** — 3 nouvelles cases (toutes défaut `true`) pour skipper des catégories d'onglets : `Onglets nœuds`, `Onglet données`, `Onglet TER ou TES`. Symétriques des cases existantes côté écriture.
- **Options d'écriture Excel** — préservation des onglets utilisateur :
  - `Conserver les autres onglets du fichier d'entrée` (`keep_other_sheets`, def. false) — copie l'input Excel vers l'output avant écriture, préservant les onglets non-format SankeyExcelParser.
  - `Réécrire les onglets SankeyExcelParser` (`rewrite_format_sheets`, def. true) — remplace l'ancien `mode_write` qui n'était pas opérationnel dans le contexte du convertisseur. Pilote `if_sheet_exists` côté pandas (`replace` vs `new`).
- **Options d'écriture Excel** — restriction aux nœuds feuilles : 2 sous-options `data_table_only_leaf_flux` et `flux_matrix_only_leaf_flux`. Si cochées, restreignent l'export du DATA_SHEET et de la matrice IO/TER aux flux dont les deux extrémités sont des nœuds sans enfants dans la hiérarchie d'agrégation.
- **Documentation technique** : nouvelle fiche [doc/sources/fr/dev/features/persistence_process_dialog.rst](doc/sources/fr/dev/features/persistence_process_dialog.rst) couvrant les modes (`CONVERTER_CONFIGS`), le layout, le pipeline frontend → backend, et l'inventaire complet des options.

### Corrections
- **« Ajuster et compléter le diagramme » respecte la vue active** : lancée depuis une vue OSP, l'action `afmReconciliation` du menu contextuel ZDD reconstruisait jusqu'ici un diagramme complet — le master était écrasé et les autres vues perdues car le serveur MFA ne connaît pas la notion de vues OSP. La réconciliation est désormais ciblée : envoi de la seule vue courante au solveur (`only_current_view: true` propagé à `app_data.toJSON`), réception via un nouveau chemin `view_only` dans `retrieveJSONResults` qui charge le résultat directement dans le DA de la vue (`DrawingAreaPersistence.fromJSON`) sans repasser par `app_data.fromJSON`, et persistance via une nouvelle méthode `saveCurrentViewToCache()` (no-op en OS, override OSP) qui recompresse `_views[current_view_id].json` après réconciliation. Master et autres vues intacts. Voir [changelog OpenSankey](submodules/OpenSankey+/submodules/OpenSankey/CHANGELOG.md) et [changelog OpenSankey+](submodules/OpenSankey+/CHANGELOG.md).
- **Casse des levelTags antagonistes préservée à la sauvegarde Excel** (#120) : le second terme d'une paire antagoniste (ex. `Organic/Fruit`) perdait ses majuscules dans la feuille *Étiquettes* (`Organic/fruit`), car `xl_write_tags_sheet` utilisait `.name` (normalisé via `_stdStr`) au lieu de `.name_unformatted`. Voir [changelog SankeyExcelParser](submodules/OpenSankey+/submodules/OpenSankey/submodules/SankeyExcelParser/CHANGELOG.md).
- **Groupes antagonistes de levelTags à N ≥ 3 tronqués à la réconciliation** (#121) : un groupe de levelTags de la forme `A/B/C` (trois groupes antagonistes ou plus) était réécrit en **deux lignes distinctes** `A/B` et `A/C` dans la feuille *Étiquettes* du fichier réconcilié, perdant l'unité du groupe. Cause : dans `xl_write_tags_sheet`, la boucle sur `tagg.antagonists_taggs` écrasait `antagonist_name`/`antagonist_tags` au lieu de les accumuler, et appendait une ligne par antagoniste. Correction : accumuler noms et tags dans des listes puis joindre par `/` pour émettre une ligne unique. Voir [changelog SankeyExcelParser](submodules/OpenSankey+/submodules/OpenSankey/submodules/SankeyExcelParser/CHANGELOG.md).
- **Facteur d'unité des labels appliqué indépendamment de l'affichage de l'unité** : définir un facteur d'échelle (ex. 1000 pour afficher en kg un flux stocké en g) ne marchait que si la case « Unité » était cochée et que le texte d'unité n'était pas vide. Le facteur est désormais appliqué dès qu'il est > 1, que l'unité soit affichée ou non. Voir [changelog OpenSankey](submodules/OpenSankey+/submodules/OpenSankey/CHANGELOG.md).
- **« Préserver les colonnes additionnelles » déplacé d'Options d'entrée vers Options de sortie + fix racine du handoff IO-input → IO-output** (OpenSankey #1220, SankeyExcelParser #71) : la case était exposée à tort dans *Options d'entrée Excel* alors que la décision est sémantiquement une décision d'écriture. Déplacée vers *Options de sortie Excel* (groupe *Fusion avec l'entrée*). Côté Flask (à la fois flow conversion et flow réconciliation), propagation server-side de `output_options.preserve_extra_columns → input_options` avant `load_sankey` pour armer le stash au bon moment. Bug racine corrigé côté SankeyExcelParser : `SankeyPandas.__init__` réinitialisait `_options` et `_extra_cols_by_sheet` après `super().__init__(other)`, donc `IOExcel(io_input.sankey)` perdait l'état de lecture (le `merge_extra_columns` faisait silencieusement no-op). Le constructeur copie désormais ces champs depuis `other` quand fourni — bug latent identique pour `preserve_input_index`, qui marchait par chance car son défaut est `True`. Voir [changelog OpenSankey](submodules/OpenSankey+/submodules/OpenSankey/CHANGELOG.md), [changelog OpenSankey+](submodules/OpenSankey+/CHANGELOG.md) et [changelog SankeyExcelParser](submodules/OpenSankey+/submodules/OpenSankey/submodules/SankeyExcelParser/CHANGELOG.md).
- **Bug critique du convertisseur** : `views.py` mergait silencieusement `output_options` par-dessus `input_options` (`{**input, **output}`). Les clés partagées (ex. `activate_data_table`) avaient toujours la valeur défaut output (`true`) — décocher « Onglet données » côté entrée n'avait aucun effet et le parser tentait quand même de lire la feuille (souvent en échouant à cause des nœuds référencés). Les deux dicts sont désormais gardés séparés et passés à `load_sankey` / `write_sankey` respectivement.
- **Onglets de tabs empilés verticalement** : utilisation du variant Chakra maison `tabs_variant_preference_tags` (qui force `tablist: { display: 'flex' }`) au lieu de `enclosed` qui héritait de `display: 'inherit'` du baseStyle Tabs OpenSankey.

## Récapitulatif — Avril 2026

Cette section consolide les évolutions livrées en avril 2026, tous modules confondus, et sert de base à la génération des notes de version.

### Ajouts
- **Visite guidée enrichie avec auto-démo** : le bouton « Visite guidée » du bandeau top lance désormais un parcours de ~21 étapes (vs 6 auparavant) qui couvre l'ensemble de l'UI — chaque bouton du bandeau top pris individuellement (nouveau / ouvrir / enregistrer / exporter / mise en page / sauvegarder en cache / tutoriels), chaque groupe de la toolbar bas (mode souris, mode position paramétrique-absolu, ajustement horizontal-vertical-plein écran, bouton d'aide), le panneau de filtres latéral gauche quand il est visible, et la séquence complète du menu de configuration droit avec bascule automatique entre les onglets Données et Style pour présenter à chaque étape un panneau concret plutôt qu'une zone vide. Si la visite est lancée sur un diagramme vide, 2 nœuds + 1 flux (valeur 100) + trois groupes de tags démo (nœud / flux / donnée) sont créés automatiquement dès le premier step pour servir de support à la démonstration, puis supprimés proprement par un step final dédié. Si le diagramme contient déjà des éléments, aucune création ni aucune suppression n'est effectuée. Les panneaux et drawers de l'UI (drawer de configuration, drawer de filtres, onglets data/style, sélection d'éléments configurables nœud/flux/DA/élément) sont ouverts et fermés automatiquement aux bons moments pendant la visite. Voir les changelogs détaillés dans [submodules/OpenSankey+/CHANGELOG.md](submodules/OpenSankey+/CHANGELOG.md) et [submodules/OpenSankey+/submodules/OpenSankey/CHANGELOG.md](submodules/OpenSankey+/submodules/OpenSankey/CHANGELOG.md).
- **Verrouillage de l'axe sur le drag de nœud (Shift + glisser)** : maintenir la touche **Shift** pendant un drag de nœud contraint le mouvement à un seul axe — horizontal (U) ou vertical (V) — choisi selon la direction initiale dominante après ~4 px de mouvement cumulé. Comportement SankeyMatic-style, utile pour aligner un nœud sans perturber son autre coordonnée. Relâcher Shift en cours de drag libère immédiatement le verrou. Fonctionne avec la sélection multiple, le mode magnétique (verrou appliqué avant le snap grille), la propagation conteneur (les enfants englobés suivent le verrou) et l'undo/redo (étape d'annulation normale comme pour un drag libre). Une nouvelle entrée « Shift + Drag (noeuds) » a été ajoutée au tableau du mode sélection de la modale d'accueil. Documentation utilisateur et développeur dans [doc/sources/fr/user/features/verrouillage_position_uv.rst](doc/sources/fr/user/features/verrouillage_position_uv.rst) / [doc/sources/en/user/features/uv_position_lock.rst](doc/sources/en/user/features/uv_position_lock.rst) (+ miroirs `dev/`).
- **Mode d'affichage englobant (container) sur les dimensions d'agrégation** : nouveau troisième mode d'affichage, en plus de l'agrégation et de la désagrégation classiques. Un nœud parent peut être rendu en même temps que ses enfants, sous forme d'un rectangle pointillé qui les englobe visuellement, avec deux variantes de répartition des flux : (a) entrées sur les enfants et sorties depuis le parent, ou (b) entrées sur le parent et sorties depuis les enfants. Les flux internes au groupe (enfant→enfant de la même dimension) restent visibles dans les deux variantes. Accessible depuis le clic droit sur un nœud parent ou enfant, via le sous-menu « Navigation hiérarchie » → sous-menu de la dimension concernée → « Englober… ». Dragger le parent englobant déplace tous les enfants en bloc ; dragger un enfant met automatiquement à jour l'enveloppe du parent et de tous ses ancêtres englobants. L'intérieur du container est click-through pour garder les petits nœuds enfants cliquables ; seule la bordure pointillée intercepte les clics. Le layout initial empile les enfants verticalement avec un écart de 10 px, mais ne touche plus rien lors d'un rechargement depuis JSON ou d'un changement de variante, pour préserver tout arrangement manuel. État sauvegardé en JSON et rejoué au reload comme au changement de vue. Documentation utilisateur et développeur dans `doc/sources/{fr,en}/{user,dev}/features/` (`mode_englobant.rst` / `enclosing_mode.rst`).
- **Nouvelle structure de documentation** : `doc/sources/` restructuré en deux projets Sphinx parallèles (`fr/` et `en/`), chacun avec une section `user/` et une section `dev/`, organisées par feature (`features/` avec `:glob:` pour auto-découverte des nouvelles pages). Templates `doc/templates/{feature-user, feature-dev}.rst` pour cadrer les nouvelles fiches de feature. L'ancien contenu (`doc/sources/index/`, `doc/sources/pages/`, `doc/sources/conf.py`) reste en place et sera archivé/supprimé dans un passage ultérieur. Le build Flask (`doc/views.py`) n'est pas encore adapté au double-langue — follow-up à traiter quand on voudra servir la doc en ligne.
- **Noms de styles par défaut traduisibles (FR/EN)** : les styles créés automatiquement à l'import (style de nœud/flux/container par défaut, étiquettes produit/secteur, import-export collés et dessus/dessous, styles unitaires) suivent désormais la langue de l'interface. Les styles renommés manuellement par l'utilisateur sont préservés.
- **Document d'architecture** : nouveau fichier [ARCHITECTURE.md](ARCHITECTURE.md) décrivant la stack 3 couches (OpenSankey → OpenSankey+ → SankeyApplication), le data model, le pipeline de rendu D3, le pattern ref-based des menus, le système de vues, la persistance, et les submodules Python (SankeyExcelParser, MFAProblem, LoginComponent). Inclut 17 pistes d'amélioration identifiées lors de la revue de code.
- **Sous-menu « Réinitialiser les intervalles verticaux »** (mode parametric) : champ d'écart vertical, bouton reset au défaut, bouton appliquer. L'écart vertical est partagé en session avec les sous-menus de centrage et minimisation des croisements.
- **Persistance de session des écarts de mise en page** : les valeurs des champs d'écart horizontal/vertical sont conservées entre ouvertures de menu pendant la session (pas sauvées en JSON). Bouton « Réinitialiser au défaut » ajouté aux sous-menus de centrage et minimisation.
- **Ecarts horizontaux/verticaux configurables pour la mise en page automatique** : les commandes de centrage et minimisation des croisements (menu contextuel) proposent désormais des champs d'écart horizontal/vertical. Idem dans le dialogue d'import Excel (section Mise en page).
- **Mise en page automatique unifiée et enrichie** : même interface Mise en page dans le menu contextuel clic-droit et le dialogue d'import Excel (section élargie, sélecteur Mode « Centrer les nœuds » / « Minimiser les croisements », bouton unique de lancement). Nouvelles options pour épingler les nœuds sans flux entrant à l'extrémité gauche et les nœuds sans flux sortant à l'extrémité droite. Traductions FR/EN complètes avec tooltips. Écarts, modes d'extrémité et mode de calcul sont partagés en session entre les deux interfaces.
- **Verrouillage colonne (u) et ligne (v) sur les nœuds** : le menu d'apparence d'un nœud expose deux champs « Colonne » et « Ligne » assortis chacun d'un bouton cadenas. Quand verrouillé, le recalcul automatique conserve la colonne et/ou la position verticale relative du nœud dans sa colonne, en préservant l'ordre entre les nœuds verrouillés. Les nœuds non verrouillés continuent d'être placés librement autour. Permet d'épingler manuellement certains nœuds tout en laissant l'algo optimiser les autres.
- **Persistance Excel de la colonne u et de la ligne v** : deux nouvelles colonnes entières optionnelles « Colonne u » / « Ligne v » (EN « Column u » / « Row v ») acceptées à l'import dans les onglets « Noeuds », « Produits » et « Secteurs ». Quand une valeur est renseignée, le nœud est automatiquement verrouillé sur cette position (sémantique : valeur fournie = épinglée). À l'export Excel, ces colonnes sont ajoutées quand au moins un nœud porte une valeur, sinon elles sont omises — aucune rupture pour les fichiers existants.
- **Intervalles, incertitude, min/max sur les flux (AFM)** : nouveau type de donnée `intervals`, champs min/max/incertitude relative (%) persistés en JSON et synchronisés avec l'export/import Excel. Panneau de configuration flux restructuré en onglets Basique/AFM. Affichage `[min - max]` sur le diagramme pour les flux intervalle.
- **Séparation type de données / affichage des intervalles** : les deux sélecteurs de la barre d'outils sont désormais indépendants (`data_source` + `interval_display`). On peut voir les intervalles données ou résultats selon la source sélectionnée. « Valeurs possibles » réservé aux données calculées. Type d'affichage affiché dans la légende.
- **Stocks et flux de recyclage** : un nœud dont la somme des flux entrants diffère de la somme des sortants affiche désormais un libellé `entrée → sortie` permettant de visualiser explicitement l'écart (stock).
- **Mode d'affichage des totaux entrants/sortants configurable** sur le libellé de valeur d'un nœud. Lorsque les flux entrants et sortants diffèrent, l'onglet valeur du menu d'apparence propose trois boutons (Σin / Σin→Σout / Σout) pour choisir ce qui est affiché. Par défaut (`Σin→Σout`), la comparaison se fait désormais sur les **chaînes après formatage** (chiffres significatifs, décimales, unités) : deux totaux qui rendent le même texte à l'écran ne montrent plus la flèche. Comportement rétrocompatible sur les diagrammes existants.
- **Stocks (Δstock) intégrés au bilan matière MFA**. Une variation de stock déclarée sur un nœud (feuille Excel `stocks`) est désormais traitée par le solveur MFAProblem comme une variable réconciliable supplémentaire dans la contrainte de bilan matière, selon la convention `Σ(entrants) − Σ(sortants) − Δstock = 0`. La feuille `stocks` accepte trois nouvelles colonnes optionnelles `uncert`, `min`, `max` qui pilotent la réconciliation. Deux nouvelles feuilles Excel **`stocks_results`** et **`stocks_analysis`** (parallèles à `results` / `analysis` pour les flux) sont produites en sortie : valeur réconciliée, intervalle libre, valeur d'entrée, sigma, nb_sigmas, classification. Ces feuilles sont à la fois écrites par le pipeline de réconciliation et lues par le pipeline d'import, ce qui permet au front de récupérer les résultats stocks via `node.stock_results`. Cross-link `alterego` entre input et output. ### Modifications
- **Refonte PR 3 du mode de positionnement paramétrique (centralisation + containers récursifs + drag local + clustering de colonnes)** : troisième et dernière passe de la refonte du mode parametric ([su-model/opensankey#1210](https://gitlab.com/su-model/opensankey/-/issues/1210), [MR !1034](https://gitlab.com/su-model/opensankey/-/merge_requests/1034)), faisant suite aux PR 1 et PR 2. Aucun changement utilisateur visible dans le cas nominal. `Class_NodePositioning.recomputeParametricLayout` devient le **seul** chemin qui écrit `position_y` en mode parametric, appelé une fois par cycle de dessin depuis `Class_DrawingArea.drawElements`. `Node.applyPosition` en branche parametric est réduit à un pass-through qui pose simplement le `transform` SVG depuis des positions déjà calculées. L'algorithme se divise en trois phases : (A) sizing bottom-up des containers en lisant la géométrie logique (sans `getBBox`), (B) stacking des colonnes top-level, (C) positionnement top-down des descendants de containers. Le drag parametric en fin de drag est explicite, avec un settle en 5 étapes (infer u, reset v, recompute v, back-calc dy, redraw immédiat). `inferPositionUFromX` a été réécrit en clustering par proximité pour éliminer les sauts de colonne à 1-2 px près observés quand deux nœuds quasi-alignés tombaient de part et d'autre de la frontière de rounding. Suppression de `restackContainerChildren`, `restackAncestorContainers` et du `setTimeout(0)` dans `setContainerMode` — remplacés par la descente récursive de phase C et un `drawElements()` explicite. **Limitation connue** : dragger l'enfant de plus petit `position_v` d'un container le fait revenir à l'ancre `container.y + margin_top` au re-stack de phase C (phase C utilise une ancre fixe). Section PR 3 complète ajoutée à [doc/sources/fr/dev/features/positionnement_parametrique.rst](doc/sources/fr/dev/features/positionnement_parametrique.rst) et son miroir EN.
- **Assainissement du mode de positionnement paramétrique (PR 1 + PR 2)** : première passe de refonte du mode parametric, sans changement utilisateur visible en nominal. PR 1 corrige des bugs silencieux : prédicat malformé dans `Node.applyPosition` (branche parametric), espacement qui ne se rafraîchissait pas lors d'un changement de valeur de data tag, saut visuel systématique à la bascule absolu → paramétrique (désormais précédée d'un back-calcul de `shape_position_dy` depuis les positions absolues courantes, avec clamp à 0 et warning console en cas d'overlap préexistant), purge indue de `position_dy` sur les nouveaux nœuds créés par désagrégation, couplage bidirectionnel `u ↔ x` dans `computeParametrization` (le calcul `position_u = round(position_x / dx)` est extrait dans une méthode `inferPositionUFromX` appelée explicitement par les call sites concernés). PR 2 unifie `shape_position_dy` comme seule source de vérité pour l'espacement vertical : tous les sites qui empilaient avec un `gap = 10` hardcodé (restack des enfants d'un container, entrée en mode container, désagrégation classique et latérale, rééquilibrage des colonnes ancêtres) sont migrés sur deux nouveaux helpers statiques `Class_NodePositioning.stackNodesVertically` / `totalStackHeight`. **Conséquence visuelle à surveiller** : à l'entrée en mode container ou à la désagrégation, l'espacement initial des enfants passe de 10 à 20 px (valeur du default style). PR 3 (à venir) centralisera le recompute paramétrique dans une `recomputeParametricLayout(scope)` qui traitera les containers comme des sous-colonnes récursives et supprimera la clause « nested container bypass » encore active. Documentation technique : [doc/sources/fr/dev/features/positionnement_parametrique.rst](doc/sources/fr/dev/features/positionnement_parametrique.rst) (miroir EN disponible).
- **Mise en page** : amélioration des groupes de layout (`groups` exposés en getter), améliorations diverses de `UpdateModeGrid`.
- **Légende** : l'offset des libellés de tag est désormais proportionnel à la taille de police.

# Migration VPS — dev.open-sankey.fr

**Ubuntu 20.04 → Ubuntu 24.04 LTS | Python 3.8 → 3.12 | Mai 2026**

---

## 1. Contexte

Migration du VPS OVH de l'ancien serveur vers un nouveau VPS. Approche progressive : service par service, en commençant par l'environnement de développement.

| | Ancien VPS | Nouveau VPS |
|---|---|---|
| OS | Ubuntu 20.04 LTS | Ubuntu 24.04 LTS |
| Python | 3.8.10 | 3.12.3 |
| Node.js | — | 22.x (via NodeSource) |
| IP | ancienne IP | 51.75.204.192 |
| Port SSH | 22 (custom) | 5378 |

---

## 2. Étapes de migration

### 2.1 Préparation du serveur

**Changer le port SSH** — Ubuntu 24.04 utilise `ssh.socket`, pas `sshd_config` :

```bash
sudo systemctl edit ssh.socket
```

Ajouter dans l'éditeur :

```ini
[Socket]
ListenStream=
ListenStream=5378
```

```bash
sudo systemctl daemon-reload
sudo systemctl restart ssh.socket
```

Autoriser le port dans le pare-feu OVH (manager OVH) et UFW :

```bash
sudo ufw allow 5378/tcp
```

**Copier la clé SSH depuis le PC Windows** (ssh-copy-id n'existe pas sous Windows) :

```powershell
type ~/.ssh/id_ed25519.pub | ssh -p 5378 ubuntu@51.75.204.192 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

Se connecter ensuite avec :

```bash
ssh -p 5378 ubuntu@51.75.204.192
```

### 2.2 Installation de Node.js 22

`pnpm` (gestionnaire de paquets du projet) requiert Node.js >= v22.13. Ubuntu 24.04 apt ne fournit que Node 18.

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install nodejs -y
```

### 2.3 Clonage du dépôt et environnement virtuel

```bash
mkdir -p ~/dev_opensankey && cd ~/dev_opensankey
git clone git@gitlab.com:su-model/sankeyapplication.git
python3 -m venv dev_opensankey
source dev_opensankey/bin/activate
pip install uwsgi
```

Copier le fichier `env` depuis l'ancien serveur (variables d'environnement : clés Stripe, DB, etc.) :

```bash
# Depuis le PC, en passant par lui comme intermédiaire :
scp -P ANCIEN_PORT ubuntu@ANCIEN_IP:~/dev_opensankey/sankeyapplication/env ./env_dev
scp -P 5378 ./env_dev ubuntu@51.75.204.192:~/dev_opensankey/sankeyapplication/env
```

### 2.4 Lancement du script de déploiement

```bash
cd ~/dev_opensankey/sankeyapplication
bash update_opensankey.sh dev
```

## 3. Corrections de compatibilité Python 3.12

Le passage de Python 3.8 à 3.12 a nécessité plusieurs corrections dans les submodules.
**Ces modifications doivent être committées dans les dépôts concernés.**

### pnpm : ERR_PNPM_IGNORED_BUILDS

```bash
cd ~/dev_opensankey/sankeyapplication/client
pnpm approve-builds
```

### flake8 : bin/archives non exclu (MFAProblem)

`flake8 --exclude submodules` dans `MFAProblem/build_server.sh` écrase le `setup.cfg`.

Modifier `submodules/MFAProblem/build_server.sh` :

```bash
# Avant :
flake8 --exclude submodules || exit_if_error $?

# Après :
flake8 --exclude submodules,bin/archives || exit_if_error $?
```

### scipy : version incompatible Python 3.12

`scipy==1.10.1` ne supporte pas Python 3.12. Modifier `submodules/MFAProblem/setup.py` :

```python
# Avant :
"scipy==1.10.1",

# Après :
"scipy>=1.11.1",
```

### numpy : version incompatible Python 3.12

`numpy==1.24.4` ne supporte pas Python 3.12. Modifier `submodules/MFAProblem/setup.py` :

```python
# Avant :
"numpy==1.24.4",

# Après :
"numpy>=1.26.0",
```

### setuptools : pkgutil.ImpImporter supprimé en Python 3.12

```bash
pip install --upgrade setuptools
```

Modifier `submodules/MFAProblem/build_server.sh` pour éviter l'isolation de build :

```bash
# Avant :
pip install .

# Après :
pip install --no-build-isolation .
```

## 4. Service systemd

Créer `/etc/systemd/system/dev_opensankey.service` :

```ini
[Unit]
Description=uWSGI instance to serve developpement version of sankeyapp
After=network.target

[Service]
User=ubuntu
Group=www-data
WorkingDirectory=/home/ubuntu/dev_opensankey/sankeyapplication
EnvironmentFile=/home/ubuntu/dev_opensankey/sankeyapplication/env
ExecStart=/home/ubuntu/dev_opensankey/dev_opensankey/bin/uwsgi --ini sankeyapp.ini

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
```

### restart_site.sh

Le script `restart_site.sh` appelle `systemctl restart/start/enable` — le service doit exister avant le premier `update_opensankey.sh`.

## 5. Nginx et SSL

Créer `/etc/nginx/sites-available/dev_opensankey` :

```nginx
server {
    server_name dev.open-sankey.fr www.dev.open-sankey.fr;

    location / {
        include uwsgi_params;
        uwsgi_pass unix:/home/ubuntu/dev_opensankey/sankeyapplication/sankeyapp.sock;
        try_files $uri /index.html;
        if ($request_method ~* "(GET|POST)") {
            add_header "Access-Control-Allow-Origin" *;
        }
    }

    location /stripe/webhook {
        include uwsgi_params;
        uwsgi_pass unix:/home/ubuntu/dev_opensankey/sankeyapplication/sankeyapp.sock;
        try_files $uri /index.html;
        if ($request_method ~* "(GET|POST)") {
            add_header "Access-Control-Allow-Origin" *;
        }
    }

    listen 80;
}
```

Activer et recharger :

```bash
sudo ln -s /etc/nginx/sites-available/dev_opensankey /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

Mettre à jour le DNS dans OVH (Zone DNS) : enregistrement A de `dev.open-sankey.fr` → `51.75.204.192`, vérifier la propagation :

```bash
dig dev.open-sankey.fr +short
```

Obtenir le certificat SSL :

```bash
sudo certbot --nginx -d dev.open-sankey.fr
```

> **Note :** ne pas inclure `www.dev.open-sankey.fr` si l'enregistrement DNS www n'existe pas.

## 6. Pour les prochaines migrations (test / prod)

Committer d'abord les corrections Python 3.12 dans les submodules (MFAProblem au minimum). Ensuite, pour chaque environnement :

1. Créer le virtualenv et cloner le repo (adapter le chemin : `test_opensankey`, `prod_opensankey`)
2. Copier le fichier `env`
3. `bash update_opensankey.sh [test|prod]`
4. Créer le service systemd (`test_opensankey.service`, `prod_opensankey.service`)
5. Créer la config nginx et activer le site
6. Mettre à jour le DNS et lancer certbot
